# Standard: Progressive Web App (PWA)

This standard defines requirements for building Progressive Web Apps that install locally, work offline, and prompt users to update when new versions are deployed.

---

## 1. Web App Manifest

Every PWA must include a static `manifest.webmanifest` file in the `public/` directory with these required fields:

| Field | Requirement |
|-------|-------------|
| `name` | Full application name (max 45 characters) |
| `short_name` | Shortened name for home screen (max 12 characters) |
| `description` | One-line description of the app |
| `start_url` | Must be `/` (root) |
| `scope` | Must be `/` (root) |
| `display` | Must be `standalone` |
| `theme_color` | Brand primary color (hex): matches `<meta name="theme-color">` |
| `background_color` | Splash screen background (hex) |
| `icons` | At least 192x192 and 512x512 PNG icons, plus one maskable icon |

### Icon Requirements

| Size | Purpose | Format |
|------|---------|--------|
| 192x192 | App icon (Android) | PNG |
| 512x512 | Splash screen, store listing | PNG |
| 512x512 | Maskable (safe zone cropping) | PNG with `"purpose": "maskable"` |
| 180x180 | Apple Touch Icon (iOS) | PNG, referenced via `<link rel="apple-touch-icon">` |
| any | Favicon | SVG preferred (`<link rel="icon" type="image/svg+xml">`) |

Generate production icons from a single SVG source using `@vite-pwa/assets-generator`:
```bash
npx @vite-pwa/assets-generator --preset minimal public/favicon.svg
```

For placeholder/development icons, use solid-color PNGs matching the `theme_color`. Replace before production deployment.

## 2. Service Worker Strategy

### Registration

Use `vite-plugin-pwa` with `registerType: 'prompt'` to generate and register the service worker. Workbox generates the service worker at build time with precaching of all static assets. The service worker must be:
- Generated by Workbox (via `vite-plugin-pwa`): no hand-rolled service worker needed
- CSP-safe: compatible with `script-src 'self'` (Workbox generates a local SW file, no CDN imports)
- Registered via the `virtual:pwa-register/vue` composable (`useRegisterSW`)

On page load, the service worker precaches all static assets (JS, CSS, HTML, fonts, images). When a new version is detected, the app prompts the user instead of auto-updating.

```typescript
// Registration via virtual:pwa-register/vue
import { useRegisterSW } from 'virtual:pwa-register/vue'

const { needRefresh, offlineReady, updateServiceWorker } = useRegisterSW({
  onRegisteredSW(swUrl, registration) {
    if (registration) {
      document.addEventListener('visibilitychange', () => {
        if (document.visibilityState === 'visible') registration.update()
      })
    }
  },
})
```

### Security Override

`vite-plugin-pwa` depends on `workbox-build`, which transitively pulls in a vulnerable version of `serialize-javascript` via `@rollup/plugin-terser`. Add this npm override to `package.json` to force the fixed version:

```json
{
  "overrides": {
    "workbox-build": {
      "@rollup/plugin-terser": "^1.0.0"
    }
  }
}
```

`@rollup/plugin-terser@^1.0.0` depends on `serialize-javascript@^7.0.3` (patched), eliminating the RCE vulnerability (GHSA-5c6j-r48x-rmvq).

### Caching Strategy

The service worker must implement:
- **Cache-first** for static assets (JS, CSS, fonts, images): fast loads from cache
- **Network-first** for navigation requests, always fetch latest HTML when online, fall back to cached SPA shell when offline
- **No caching** for API requests (`/api/*`): let the application handle API errors

```javascript
// Navigation: network-first with SPA fallback
self.addEventListener('fetch', (event) => {
  if (request.url.includes('/api/')) return  // skip API requests

  if (request.mode === 'navigate') { // browser route request
    event.respondWith(
      fetch(request)
        .then((response) => { /* cache and return */ })
        .catch(() => caches.match('/'))  // SPA fallback
    )
    return
  }

  // Static assets: cache-first
  event.respondWith(
    caches.match(request).then((cached) => cached || fetch(request))
  )
})
```

### Version Detection

The service worker must check for updates:
1. **On every page load**: call `registration.update()` after registration
2. **On visibility change**: when the user returns to the tab after being away
3. **Never auto-update**: always prompt the user first

```typescript
// useRegisterSW from virtual:pwa-register/vue handles all of this automatically:
// - Registration and update detection
// - needRefresh becomes true when a new SW is waiting
// - offlineReady becomes true on first install
const { needRefresh, offlineReady, updateServiceWorker } = useRegisterSW({
  onRegisteredSW(swUrl, registration) {
    if (registration) {
      document.addEventListener('visibilitychange', () => {
        if (document.visibilityState === 'visible') registration.update()
      })
    }
  },
})
```

### User-Initiated Updates (Prompt Behavior)

When a new service worker is waiting to activate, the app must prompt the user. When the user accepts:

1. Post a `SKIP_WAITING` message to the waiting worker
2. The worker calls `self.skipWaiting()` to activate immediately
3. Listen for the `controllerchange` event and reload the page

```typescript
// App side: user clicks "Update now"
// updateServiceWorker() from useRegisterSW handles skipWaiting + reload
await updateServiceWorker()

// Workbox (generated by vite-plugin-pwa) handles the service worker side:
// - Listens for the SKIP_WAITING message
// - Calls self.skipWaiting()
// - The app reloads on controllerchange
```

### Why Prompt Instead of Auto-Update

- Auto-updating silently replaces the app, which can cause data loss if the user has unsaved state
- Prompting gives the user control over when to update
- Enterprise apps especially benefit from explicit update control

## 3. Install Prompt

### Browser Install Prompt

Listen for the `beforeinstallprompt` event at **module scope** (not in a lifecycle hook) because it fires before components mount:

1. **Store the event**: save it so the install can be triggered later from a custom UI button
2. **Do not call `preventDefault()`**: let the browser show its native install mini-infobar alongside your custom button
3. **Show a branded prompt**: display an in-app banner or button as a secondary install trigger
4. **Call `event.prompt()`**: when the user clicks Install on your custom UI
5. **Listen for `appinstalled`**: to detect successful installation and hide the prompt

```typescript
// Module scope: captures the event before any component mounts
window.addEventListener('beforeinstallprompt', (e: Event) => {
  deferredPrompt = e
  showInstallBanner = true
})
```

Why no `preventDefault()`: calling it suppresses the browser's native install banner and produces a console warning. Omitting it lets the browser show its native prompt and keeps the console clean. Your custom button still works via the stored event.

### Install Prompt UX Requirements

- The install prompt must be **dismissible**: provide a "Not now" option
- Once dismissed, do not show again during the same session
- Once installed, detect via `matchMedia('(display-mode: standalone)')` and never show again
- Position the prompt where it does not block primary content (bottom of viewport recommended)
- Register event listeners at **module scope**, not in component lifecycle hooks , `beforeinstallprompt` fires before Vue components mount

## 4. Update Prompt

When the service worker detects new content (the `updatefound` event fires and the new worker reaches the `installed` state):

1. **Show a non-blocking banner**: at the top of the viewport
2. **Provide "Update now" button**: posts `{ type: 'SKIP_WAITING' }` to the waiting worker and reloads on `controllerchange`
3. **Provide "Later" button**: dismisses the banner (update will apply on next full page load)
4. **Never force-update**: the user must initiate the update

### Update Prompt UX Requirements

- The banner must be clearly visible but not obstruct the UI
- Use `role="alert"` for accessibility
- The "Update now" action should feel instant, the page reloads after the new SW activates
- The "Later" action must dismiss the prompt (not auto-reappear until the next navigation)

## 5. HTML Meta Tags

The `index.html` must include these PWA-related tags in `<head>`:

```html
<link rel="icon" type="image/svg+xml" href="/favicon.svg" />
<link rel="manifest" href="/manifest.webmanifest" />
<link rel="apple-touch-icon" href="/apple-touch-icon-180x180.png" />
<meta name="theme-color" content="#4f46e5" />
<meta name="mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="default" />
```

The `<link rel="manifest">` points to the static `public/manifest.webmanifest` file, which is served directly by Vite in dev and copied to `dist/` in production.

## 6. Content Security Policy

CSP **must** be set via HTTP response headers on the production web server or CDN, not via a `<meta>` tag. Reasons:
- `frame-ancestors` cannot be set via meta tag
- Nonce-based `script-src` requires server-side header generation
- Meta-tag CSP conflicts with build tool and plugin inline scripts during development

Include `worker-src 'self'` and `script-src 'self'` in the production CSP header. The Workbox-generated service worker is a local file, no CDN origins are needed:

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self';
```

Do not use `worker-src *` or allow external origins. `vite-plugin-pwa` with default settings generates a local service worker file, no external Workbox CDN imports are needed.

## 7. Offline Behavior

### Precaching

Workbox (via `vite-plugin-pwa`) precaches all static assets matching the configured `globPatterns` from the build output. This means:
- The app shell (HTML, CSS, JS) is available offline after first visit
- Images/fonts/icons referenced in the build are cached
- Cache versioning and cleanup are handled automatically by Workbox

### API Requests

API requests (`/api/*`) are **not cached** by the service worker. When offline:
- The app shell loads from cache
- API calls fail gracefully (the app's error handling manages this)
- Display appropriate "offline" messaging for data-dependent views

### Navigation Fallback

The service worker returns the cached `index.html` for all navigation requests that fail to reach the network (SPA fallback). API routes (`/api/*`) are excluded, they are never intercepted by the service worker.

This way client-side routing works offline, the browser gets the cached SPA shell, and Vue Router handles the route.

## 8. Development Mode

Skip service worker registration in development. Use an `import.meta.env.DEV` guard in the registration composable:

Configure `vite-plugin-pwa` with `devOptions: { enabled: false }` (the default) to disable the service worker in development:

```typescript
VitePWA({
  // ...
  devOptions: {
    enabled: false,  // No SW in dev: avoids stale cache issues
  },
})
```

This approach:
- **Dev**: no service worker, no stale caches, no CSP violations from inline scripts
- **Production build**: Workbox generates the service worker with precached assets; `useRegisterSW` from `virtual:pwa-register/vue` handles registration

The manifest is generated by the plugin in production builds. In dev mode, a static `manifest.webmanifest` in `public/` can be used as a fallback if needed.

### Dev Auth Mock

When developing the frontend without a backend, auth bootstrap requests (`/api/auth/me`, `/api/auth/csrf-token`) will 404. Add a dev-only Vite plugin to intercept these before the proxy:

```typescript
function devAuthMock(): Plugin {
  return {
    name: 'dev-auth-mock',
    apply: 'serve',
    configureServer(server) {
      server.middlewares.use((req, res, next) => {
        if (req.url === '/api/auth/me') {
          res.writeHead(200, { 'Content-Type': 'application/json' })
          res.end('null')
          return
        }
        if (req.url === '/api/auth/csrf-token') {
          res.writeHead(200, { 'Content-Type': 'application/json' })
          res.end(JSON.stringify({ token: 'dev-csrf-' + Date.now() }))
          return
        }
        next()
      })
    },
  }
}
```

Disable this plugin by setting `VITE_API_ENABLED=true` in `.env` when a real backend is available.

## 9. Testing Checklist

| Test | Expected Result |
|------|----------------|
| First visit on HTTPS | Service worker registers, assets are precached |
| Reload after first visit | App loads from cache (verify in DevTools > Application > Cache Storage) |
| Deploy new version, reload | Update prompt appears |
| Click "Update now" | Page reloads with new version |
| Click "Later" | Banner dismissed, old version continues |
| Visit on mobile Chrome | "Add to Home Screen" prompt appears |
| Click "Install" | App installs, opens in standalone mode |
| Open installed app offline | App shell loads, API errors handled gracefully |
| Lighthouse PWA audit | Score 100 (all PWA criteria met) |
| `manifest.webmanifest` accessible | Returns valid JSON with all required fields |
| Icons load at all sizes | 192x192, 512x512, apple-touch-icon all resolve |

## 10. Build Plugin Reference

Use `vite-plugin-pwa` with the `VitePWA()` plugin. Workbox handles all precache manifest generation automatically at build time:

```typescript
import { VitePWA } from 'vite-plugin-pwa'

VitePWA({
  registerType: 'prompt',
  injectRegister: false,
  manifest: {
    name: 'App Template',
    short_name: 'AppTemplate',
    description: 'Vue 3 PWA Application Template',
    theme_color: '#4f46e5',
    background_color: '#ffffff',
    display: 'standalone',
    scope: '/',
    start_url: '/',
    icons: [
      { src: 'pwa-192x192.png', sizes: '192x192', type: 'image/png' },
      { src: 'pwa-512x512.png', sizes: '512x512', type: 'image/png' },
      { src: 'pwa-512x512.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
    ],
  },
  workbox: {
    globPatterns: ['**/*.{js,css,html,svg,png,ico,woff2}'],
    navigateFallback: 'index.html',
    navigateFallbackDenylist: [/^\/api\//],
  },
  devOptions: {
    enabled: false,
  },
})
```

Key properties:
- `registerType: 'prompt'`: no auto-update; the app controls when `skipWaiting` is called
- `injectRegister: false`: the composable handles registration via `virtual:pwa-register/vue`
- `workbox.globPatterns`: defines which files Workbox precaches from the build output
- `workbox.navigateFallback`: SPA fallback for offline navigation
- `workbox.navigateFallbackDenylist`: excludes API routes from the fallback
