# Red Team Offensive Security Assessment

**Location:** `.claude/security/redteam/`

Read `.claude/security/redteam/CLAUDE.md` for the full execution protocol before starting any assessment.

---

## Mandatory Dual-Analysis Protocol

Every assessment MUST combine:
1. **AI-driven analysis**: read target source, follow skill .md files, produce structured findings
2. **Deterministic script execution**: run .js scripts for HTML reports. **AI analysis alone is NOT sufficient.**

---

## Agent Pipeline

```
Phase 1 (parallel):     01-recon-agent + 02-code-analysis-agent
Phase 2 (parallel):     05-dependency + 06-infrastructure + 07-sast + 08-secrets
Phase 3 (sequential):   03-poc-execution-agent (requires Phase 1 outputs)
Phase 4 (sequential):   04-recommendation-agent (requires Phase 3 outputs)
```

Agent skills are in `.claude/security/redteam/skills/`.

## Recon Tools

10 JavaScript recon wrappers in `.claude/security/redteam/tools/recon/`. Each uses a 3-step dispatcher (binary on PATH → Node-native fallback → structured `{error}` JSON), so the recon phase runs on every supported OS without apt/brew dependencies. Shared helpers live in `tools/recon/_runner.js`.

| Tool | Intelligence Gathered | Node-native fallback |
|------|----------------------|----------------------|
| `dns_enum.js` | DNS records (A, AAAA, MX, TXT, SOA, NS, CNAME) | `node:dns/promises` (AXFR + DNSSEC noted as binary-only) |
| `whois_lookup.js` | Domain registrar, registrant, dates | `whois-json` npm package over TCP/43 |
| `subdomain_discovery.js` | Subdomains via passive/active enumeration | crt.sh REST + bundled DNS brute-force wordlist |
| `port_scan.js` | Open ports, services, versions, banners | TCP-connect via `net.Socket`, top-100 ports, concurrency-capped at 32 |
| `tls_scan.js` | Certificate details, cipher suites, TLS versions | `tls.connect()` enumeration of protocols + cert (subject/issuer/SAN/expiry); "no TLS service" handled gracefully |
| `http_headers.js` | Security header presence/absence | Native `http`/`https` (always; never required curl) |
| `tech_fingerprint.js` | Web servers, frameworks, libraries | Header + body signature parsing (Vue/React/Drupal/Rails/WordPress markers) |
| `waf_detect.js` | WAF type identification | 3-probe heuristic (clean / XSS / shellshock) + vendor signature table |
| `endpoint_discovery.js` | API endpoints, methods, parameters | 80-path bundled wordlist + concurrent HEAD/GET |
| `ct_search.js` | Certificate Transparency log entries | crt.sh REST (always native) |

### Install Dependencies
```bash
cd .claude/security/redteam
npm install   # bundles the @anthropic-ai/claude-agent-sdk-win32-x64 platform package on Windows
# Optional. Only needed if you want the richer external-binary output:
bash scripts/install_recon_deps.sh         # Linux/macOS (apt/brew)
pwsh scripts/install_recon_deps.ps1        # Windows (winget/scoop/choco)
```

### Additional scanner wrappers
| Script | Purpose | Fallback when binary missing |
|---|---|---|
| `scripts/nmap_scan.js` | Port scan | Native TCP-connect (shared with `tools/recon/port_scan.js`) |
| `scripts/semgrep_scan.js` | SAST | Returns `{status:"not_installed", install_instructions}` |
| `scripts/trufflehog_scan.js` | Secrets | Built-in regex sweep (~20 patterns: AWS keys, GitHub tokens, OpenAI keys, JWT, PEM, etc.) |
| `scripts/osv_scan.js` | Vulnerable deps | OSV.dev REST API against `package-lock.json` / `pnpm-lock.yaml` |
| `scripts/zap_scan.js` | OWASP ZAP | Manual-run guide; `--report <file>` chains to `zap_parse.js`; `--auto-docker` runs `zap-baseline.py` if Docker is on PATH |

Blue team and red team findings cross-reference:

## Safety Rules

- Do not read `.env` files or production secrets
- Use `[REDACTED-*]` placeholders for credential values
- Do not execute exploits against production systems
- Do not modify application source code during assessment
- All HTML reports must be script-generated, never hand-crafted
