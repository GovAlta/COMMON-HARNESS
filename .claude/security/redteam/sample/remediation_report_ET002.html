REM-05 — Mock Authentication Driver Active in Production

CRITICAL Quick Win Verified

Related PoCs

PoC-05 PoC-06

Root Cause

The AUTH_DRIVER environment variable defaults to 'mock' when not explicitly set (apps/api/src/services/auth.service.ts, line 65). The mock driver at packages/auth/src/drivers/mock.driver.ts lines 63-87 accepts arbitrary user selection via query parameters with no cryptographic validation, allowing any caller to authenticate as any hardcoded user including admin. The callback endpoint (mock.driver.ts lines 77-86) directly trusts the mockUserId query parameter without HMAC, nonce, or state verification.

    const mockUserId = req.query.mockUserId as string

    if (!mockUserId) {
      throw new Error('Mock callback requires mockUserId parameter')
    }

REM-13 — Trust Proxy Misconfiguration / Session Cookie Failure

HIGH Verified

Related PoCs

PoC-13

Root Cause

The Express application at apps/api/src/app.ts does not call app.set('trust proxy', ...) anywhere in the codebase. The session middleware at line 108 sets cookie.secure: true when NODE_ENV === 'production'. Behind Render's reverse proxy and Cloudflare CDN, Express sees plain HTTP connections and refuses to set Set-Cookie headers for secure cookies, breaking all session functionality in production.

REM-11 — Auth Callback CSRF Exemption Too Broad

MEDIUM Verified

Related PoCs

PoC-11

Root Cause

The CSRF middleware at apps/api/src/middleware/csrf.middleware.ts line 34 uses req.path.includes('/auth/callback') which is an overly broad substring match. Any path containing the string '/auth/callback' anywhere (e.g., /api/v1/admin/auth/callback/settings) would bypass CSRF protection. Combined with the mock driver's lack of cryptographic validation, this enables login CSRF attacks.

  }
Replacement Code
  // Skip CSRF for the specific authentication callback endpoint (handled by auth providers)
  // Use exact path match to prevent bypassing CSRF on other endpoints
  if (req.path === '/api/v1/auth/callback') {

REM-15 — Open Redirect via WEB_URL Default

Root Cause

  /**
   * Get validated redirect URL from environment.
   * Only allows URLs matching known safe patterns.
   */
  private getSafeRedirectUrl(): string {
    const webUrl = process.env.WEB_URL || 'http://localhost:5173'

    // In production, validate the URL is HTTPS and not localhost
    if (process.env.NODE_ENV === 'production') {
      try {
        const parsed = new URL(webUrl)
        if (parsed.protocol !== 'https:') {
          console.error(`WARNING: WEB_URL uses non-HTTPS protocol: ${parsed.protocol}`)
        }
        if (parsed.hostname === 'localhost' || parsed.hostname === '127.0.0.1') {
          console.error('WARNING: WEB_URL points to localhost in production.')
        }
      } catch {
        console.error(`WARNING: WEB_URL is not a valid URL: ${webUrl}`)
      }
    }

    // Strip trailing slash to prevent double-slash in path construction
    return webUrl.replace(/\/$/, '')
  }
