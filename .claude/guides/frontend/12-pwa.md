# Skill: Progressive Web App (PWA)

This skill covers implementing a fully functional PWA in the Vue 3 + Vite template, including service worker registration, install prompt, update prompt, manifest configuration, and placeholder icons.

Implements standard `06-pwa.md`.

---

## 1. Dependencies

Install `vite-plugin-pwa`; the standard community library for PWA support in Vite projects:

```bash
npm install -D vite-plugin-pwa@^1.2.0
```

This provides the `VitePWA()` Vite plugin and the `virtual:pwa-register` module for service worker registration. Workbox generates the service worker with precaching automatically at build time.

### Security Override

`vite-plugin-pwa` depends on `workbox-build`, which transitively pulls in `@rollup/plugin-terser` -> `serialize-javascript`. Older versions of `serialize-javascript` carry an RCE vulnerability (GHSA-5c6j-r48x-rmvq). Add this npm override to `package.json` to force the fixed version:

```json
{
  "overrides": {
    "workbox-build": {
      "@rollup/plugin-terser": "^1.0.0"
    }
  }
}
```

`@rollup/plugin-terser@^1.0.0` depends on `serialize-javascript@^7.0.3` (the patched version), eliminating the vulnerability. After adding the override, run `npm install` to regenerate the lockfile.

## 2. Service Worker

The service worker is generated automatically by Workbox (via `vite-plugin-pwa`) at build time. You do not write `public/sw.js` by hand. The `VitePWA()` plugin configuration in section 4 controls the caching strategy:

- **Precaching**: Workbox precaches all build output assets (JS, CSS, HTML, fonts, images) with content-hash-based revisions
- **Navigation fallback**: `navigateFallback: 'index.html'` returns the cached SPA shell for all navigation requests when offline
- **API exclusion**: `navigateFallbackDenylist: [/^\/api\//]` prevents API routes from being intercepted
- **Runtime caching**: additional `runtimeCaching` rules can be added for specific patterns (e.g., Google Fonts)

Workbox handles cache versioning, cleanup of stale caches, and the `SKIP_WAITING` message listener automatically when `registerType: 'prompt'` is configured.

## 4. Vite Configuration: `VitePWA()` Plugin

Add the `VitePWA()` plugin to `vite.config.ts`:

```typescript
import { VitePWA } from 'vite-plugin-pwa'

export default defineConfig({
  plugins: [
    vue(),
    tailwindcss(),
    Components({ resolvers: [PrimeVueResolver()] }),
    VitePWA({
      registerType: 'prompt',
      injectRegister: false,
      manifest: {
        name: 'App Template',
        short_name: 'AppTemplate',
        description: 'Vue 3 PWA Application Template',
        theme_color: '#4f46e5',
        background_color: '#ffffff',
        display: 'standalone',
        scope: '/',
        start_url: '/',
        icons: [
          { src: 'pwa-192x192.png', sizes: '192x192', type: 'image/png' },
          { src: 'pwa-512x512.png', sizes: '512x512', type: 'image/png' },
          { src: 'pwa-512x512.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
        ],
      },
      workbox: {
        globPatterns: ['**/*.{js,css,html,svg,png,ico,woff2}'],
        navigateFallback: 'index.html',
        navigateFallbackDenylist: [/^\/api\//],
      },
      devOptions: {
        enabled: false,
      },
    }),
    pwaDevFallback(),
  ],
  // ... rest of config
})
```

Key settings:
- `registerType: 'prompt'`; the service worker does not auto-update; the app controls when `skipWaiting` is called
- `injectRegister: false`; disables auto-injection of the registration script; the `usePwa.ts` composable handles registration via `virtual:pwa-register`
- `manifest`; the web app manifest is generated by the plugin (no separate `public/manifest.webmanifest` file needed)
- `workbox.globPatterns`; precaches all static assets from the build
- `workbox.navigateFallback`; returns `index.html` for navigation requests when offline (SPA fallback)
- `workbox.navigateFallbackDenylist`; excludes `/api/*` from the navigation fallback
- `devOptions.enabled: false`; service worker is not active in dev mode

### Dev Fallback Plugin

Add a lightweight dev-only plugin that intercepts auth bootstrap requests when no backend is running:

```typescript
import type { Plugin } from 'vite'

function pwaDevFallback(): Plugin {
  return {
    name: 'pwa-dev-fallback',
    apply: 'serve',
    configureServer(server) {
      server.middlewares.use((req, res, next) => {
        if (req.url === '/api/auth/me') {
          res.writeHead(200, { 'Content-Type': 'application/json' })
          res.end('null')
          return
        }
        if (req.url === '/api/auth/csrf-token') {
          res.writeHead(200, { 'Content-Type': 'application/json' })
          res.end(JSON.stringify({ token: 'dev-csrf-' + Date.now() }))
          return
        }
        next()
      })
    },
  }
}
```

Disable by setting `VITE_API_ENABLED=true` in `.env` when a real backend is running.

## 5. HTML Meta Tags

Add PWA meta tags to `index.html` `<head>`:

```html
<link rel="icon" type="image/svg+xml" href="/favicon.svg" />
<link rel="manifest" href="/manifest.webmanifest" />
<link rel="apple-touch-icon" href="/apple-touch-icon-180x180.png" />
<meta name="theme-color" content="#4f46e5" />
<meta name="mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="default" />
```

The `<link rel="manifest">` points to the static `public/manifest.webmanifest` file, which is served directly by Vite in dev and copied to `dist/` in production.

**Do not** use a CSP `<meta>` tag: it conflicts with build tool inline scripts. Set CSP via HTTP response headers on the production web server. Include `worker-src 'self'` for service worker registration.

## 6. PWA Composable: `src/composables/usePwa.ts`

Two composables handle install and update flows:

### Install Prompt

```typescript
import { ref, onMounted } from 'vue'

interface BeforeInstallPromptEvent extends Event {
  prompt(): Promise<void>
  userChoice: Promise<{ outcome: 'accepted' | 'dismissed' }>
}

const installPromptEvent = ref<BeforeInstallPromptEvent | null>(null)
const isInstallable = ref(false)
const isInstalled = ref(false)

// Module-scope listeners: beforeinstallprompt fires before components mount
if (typeof window !== 'undefined') {
  if (window.matchMedia('(display-mode: standalone)').matches) {
    isInstalled.value = true
  }

  window.addEventListener('beforeinstallprompt', (e: Event) => {
    // Do not call preventDefault(): let Chrome show its native install banner.
    // Store the event so our custom Install button can also trigger the prompt.
    installPromptEvent.value = e as BeforeInstallPromptEvent
    isInstallable.value = true
  })

  window.addEventListener('appinstalled', () => {
    isInstalled.value = true
    isInstallable.value = false
    installPromptEvent.value = null
  })
}

export function usePwaInstall() {
  async function promptInstall(): Promise<boolean> {
    if (!installPromptEvent.value) return false
    await installPromptEvent.value.prompt()
    const { outcome } = await installPromptEvent.value.userChoice
    if (outcome === 'accepted') {
      isInstallable.value = false
      installPromptEvent.value = null
    }
    return outcome === 'accepted'
  }

  function dismissInstall(): void {
    isInstallable.value = false
  }

  return { isInstallable, isInstalled, promptInstall, dismissInstall }
}
```

Key points:
- Event listeners are registered at **module scope**, not in `onMounted`; `beforeinstallprompt` fires before components mount
- `preventDefault()` is **not called**: Chrome shows its native install banner and the console stays clean
- The stored event still allows our custom Install button to trigger the prompt via `event.prompt()`
- Already-installed detection via `display-mode: standalone` media query
- Once dismissed, `isInstallable` is set to `false` for the current session

### Update Prompt

```typescript
import { useRegisterSW } from 'virtual:pwa-register/vue'

export function usePwaUpdate() {
  const {
    needRefresh,
    offlineReady,
    updateServiceWorker,
  } = useRegisterSW({
    onRegisteredSW(swUrl, registration) {
      // Check for updates when the user returns to the tab
      if (registration) {
        document.addEventListener('visibilitychange', () => {
          if (document.visibilityState === 'visible') {
            registration.update()
          }
        })
      }
    },
    onRegisterError(error) {
      console.warn('SW registration failed:', error)
    },
  })

  async function updateApp(): Promise<void> {
    await updateServiceWorker()
  }

  function dismissUpdate(): void {
    needRefresh.value = false
  }

  return { needRefresh, offlineReady, updateApp, dismissUpdate }
}
```

Key points:
- `useRegisterSW` from `virtual:pwa-register/vue` handles service worker registration, update detection, and the prompt flow
- `registerType: 'prompt'` (set in the Vite config) means the SW does not auto-update; `updateServiceWorker()` must be called explicitly
- `onRegisteredSW` callback adds a visibility change listener to check for updates when the user returns to the tab
- `needRefresh` and `offlineReady` are reactive refs provided by the composable
- `updateServiceWorker()` calls `skipWaiting` on the waiting worker and reloads the page

## 9. App.vue Integration

Import and include both PWA components in `App.vue`:

```vue
<script setup lang="ts">
import PwaInstallPrompt from '@/components/pwa/PwaInstallPrompt.vue'
import PwaUpdatePrompt from '@/components/pwa/PwaUpdatePrompt.vue'
// ... other imports
</script>

<template>
  <!-- PWA prompts (always rendered, visibility controlled internally) -->
  <PwaUpdatePrompt />
  <PwaInstallPrompt />

  <!-- ... rest of template -->
</template>
```

Both components are always mounted but only visible when their conditions are met (`needRefresh`, `isInstallable`). They use `<Transition>` for smooth entry/exit animations.

## 10. Icon Generation

For production, generate proper icons from your SVG source:

```bash
npx @vite-pwa/assets-generator --preset minimal public/favicon.svg
```

This generates all required PNG sizes from the SVG. Place the output files in `public/`:
- `pwa-192x192.png`
- `pwa-512x512.png`
- `apple-touch-icon-180x180.png`

The template ships with placeholder icons (solid indigo squares). Replace them before production deployment.

## 11. Update Flow Summary

```
User visits app
  → vite-plugin-pwa registers the Workbox-generated service worker
  → All static assets precached by Workbox (based on globPatterns)
  → App works offline

Developer deploys new version
  → User reloads or returns to tab
  → registration.update() detects new service worker
  → useRegisterSW sets needRefresh = true
  → PwaUpdatePrompt appears: "Update Available"
  → User clicks "Update now"
  → updateServiceWorker() calls skipWaiting on the waiting worker
  → controllerchange fires → page reloads with new version
```
